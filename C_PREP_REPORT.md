# Заготовка хода: проверка без сети

Ветка `final/c-prep`, база `debe636`. `заготовка=-` и `ms.spec=miss` — разные вещи: первое относится к `/api/prepare`, второе — к несовпадению рамки решения правил и модельного разбора внутри `startJob`. Теперь есть отдельное `ms.prepare=hit|miss`, а настоящий prepare с нулевым опережением показывается как `заготовка=0`.

## Условия и тесты

Имена ниже — файлы в `src/game/`, кроме явно указанных `server/`.

| Условие | Отправка / использование заготовки; покрытие |
| --- | --- |
| Scribe через воркер | После ≥160 мс речи и ≥450 мс тишины готовится доступный partial; финал без изменений не дублирует запрос. Без partial остаётся ранний commit. `listen.test.ts`, `sttStream.test.ts`. |
| Яндекс | Нынешний `recognize(pcm, signal)` принимает целую запись **после** паузы, промежуточного текста нет. Prepare неоткуда послать; дополнительное платное распознавание не добавлено. Провайдерного запрета на уже доступный текст в хуках нет. `listen.test.ts` (все три паузы), `useVoiceTurn.lifecycle.test.ts`, `useMeeting.test.ts`. |
| Scribe выключен / не подключился | `?stt=off`, сохранённый выбор, `health.scribe=false`, ошибка URL/WS, таймаут подключения 4 с, переполнение очереди, обрыв/неверный ответ → Яндекс. После потока, так и не ставшего ready, повтор подключения блокируется на 60 с. Без пригодного текста prepare нет. `sttMode.test.ts`, `sttStream.test.ts`, `listen.test.ts`. |
| iPhone/iPad/Safari | Запрета prepare нет; iOS открывает микрофон только на свой ход, Mac держит открытым. Задержка микрофона/потока может съесть опережение. Исправлено исключение до fetch при отсутствии `AbortSignal.timeout` именно в prepare. `useVoiceTurn.lifecycle.test.ts`, `useVoiceTurn.test.ts`, `api.test.ts`; ветки захвата — `pcmStream.test.ts`. |
| 3D / 2D / первый ход | Общие `useMeeting` и `useVoiceTurn`, пустая история разрешена. Переход 3D→2D сохраняет заготовку. В 3D открытое меню ставит слушание на паузу. `useMeeting.test.ts` (оба вида, первый ход, переключение), `useVoiceTurn.lifecycle.test.ts` (paused), `server/prepare.test.ts` (первый и следующий ход). |
| Коротко / средне / долго | Законченную фразу отправляют через 600/900/1400 мс; без текста или при неясном хвосте — 1000/1500/2300; оборванную — 2000/2600/3600. Ранний порог один: 450 мс. Поздний финал после close/dispose/отправки игнорируется; новый текст получает новый ключ. `listen.test.ts`, `sttStream.test.ts`, `server/speed.test.ts`. |

Ошибка сети/таймаут 10 с/HTTP-отказ не считаются принятой заготовкой. Одинаковый запрос не повторяется 50 с. `useMeeting.test.ts`, `api.test.ts`. |

Дубликат готового/выполняющегося job теперь бесплатен по квоте. У turn отдельный лимит: он может отклонить даже подготовленный ход. `server/prepare.test.ts`, `server/limits.test.ts`, `server/contractMatrix.test.ts`. |
| Ключ | Изменение текста (включая пунктуацию), содержимого дела, истории, существенного offer, accept/walkAway, natural/marks, модели или включения opener требует другого job. Реакция значима только без opener. Порядок полей, пустой/отфильтрованный offer, отсутствующий флаг вместо false, ID вместо того же полного дела и параметры TTS промаха больше не создают. `server/prepare.test.ts`. |
| Cookie / IP | Same-origin cookie отправляется. Ворота отклоняют отсутствующий/испорченный/истёкший пропуск (401). Чужая проверенная сессия не получает job. Смена IP при **той же проверенной сессии** больше не вызывает miss; аноним по-прежнему привязан к IP. `api.test.ts`, `server/prepare.test.ts`, `server/gate.test.ts`. |
| Время / процесс / отмена | Завершённый job удаляется через 60 с; другой процесс/перезапуск его не видит. Другой ключ той же сессии отменяет ещё не прикреплённую заготовку. Ошибочный/остановленный job не используется. Turn, пришедший первым, стартует сам; поздний одинаковый prepare не запускает второй job. Повтор законченного turn использует обычный кэш. `server/prepare.test.ts`, `server/speed.test.ts`. |
| Внутренний `spec=miss` | Правила и разметчик выбрали разные рамки — неподтверждённая реплика отменяется/переписывается; уже озвученное решение фиксируется. Это возможно **при успешном prepare**. Поведение сохранено: `server/speed.test.ts`, `server/appHybrid.test.ts`, `server/appOpener.test.ts`. |

## Исправления и ограничения

- Ранний partial вместо обязательного ожидания финала; защита от дубликатов partial/final, неверного языка и неподходящих сегментов.
- Стабильный ключ, привязка к проверенной сессии без IP, квота только на новые jobs; TTS-параметры не запускают повторный LLM. Наличие opener учитывается, чтобы не подменить текст хода.
- Prepare совместим с отсутствием `AbortSignal.timeout`; отказ и устаревшая/несовпадающая заготовка не подавляют обычную реакцию клиента.
- Счётчики заглушек проверяют один вызов разметчика/реплики для совпадающих prepare/turn, повторов и гонок. Исправленный текст — другой вход: старую работу отменяем, но уже потраченные провайдером токены вернуть нельзя. Пунктуацию и существенные условия не склеиваем ради попадания в кэш.

Яндекс без partial, квоты, ограничения микрофона iOS, TTL и хранение jobs в процессе оставлены: это ограничения данных, расходов и жизненного цикла. Нет сети и живого iPhone: причину конкретной партии капитана и задержку ~1,5 с на проде подтвердить нельзя. Тесты платформ моделируют lifecycle, а не Safari/Web Audio на устройстве.
