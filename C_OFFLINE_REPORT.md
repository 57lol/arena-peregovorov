# Разбор offline — 19.10.2026

Ветка `final/c-offline`, база `7140938`. Проверка локальная, модели — заглушки.

Найденные пути и исправления:

- **Блокнот / принятие:** `isNotebookLine()` немедленно возвращал `offline`, вообще не вызывая доступные модели. Убран обход; результат размечают модели, повтор берётся из кэша. Ожидание opener объясняет `разметка=заход`; воспроизведено через API для 419 и 805 мс. В исходном файле 12 примеров без текстов игроков: причину всех заявленных 33 ходов доказать по ним нельзя.
- **Быстрые исключения:** обращение к `e.message.slice()` при `throw null` или строке ломало переход к исправному запасному и приводило к offline. Теперь любые отказы транспорта и неверная схема обрабатываются безопасно; offline возможен только после отказа всех настроенных разметчиков.
- **quick/main:** отдельный успешный quick раньше игнорировался, если у main нет backup. Теперь учитывается и поздний ответ после окна quick. Запросы переиспользуются по паре провайдер/модель; совпавшие main/backup/quick вызываются один раз, включая отказ.
- **validate/groundAnalysis:** убрана повторная обработка свежего ответа. Локальное исключение после правильного JSON отделено от ошибки провайдера: используем исправный ответ другого разметчика; если локальный сбой затронул оба, возвращаем ошибку хода, не подменяем её offline. Это проверено инъекцией `ReferenceError`; реального обращения к неопределённому `said` в текущем коде не найдено.
- **Кэш:** валидный JSON с повреждённой структурой раньше вызывал исключение до запросов моделей, а не offline. Теперь структура проверяется, повреждение считается промахом. `cache.ts:cached()` не участвует в анализе (`peek/put`); его AbortError относится к общему запросу голоса. Проверены отмена заготовки, сохранение оплаченного разбора, повтор из кэша и совместный prepare/turn.
- **Спекуляция:** правила создают только предварительную рамку голоса; итог выбирается из main/quick. В рамку добавлен тот же `said`, что используется моделями. Проверены оба порядка ответов, конфликт, отмена голосовой рамки и отказ одного/обоих разметчиков. Кнопка ухода явно имеет `source: button`, модели не вызывает. Явно выбранный режим без моделей остаётся `offline(rules)`.

Журнал `[ход]`: `разбор=offline(timeout|abort|error:<класс>)`; разные причины объединяются через `+`. Поля `разметчик_main`, `разметчик_backup`, `разметчик_quick` содержат длительность запроса в мс и исход. `-` означает отсутствие вызова, `-(pending)` — запрос ещё выполняется. Длительности измеряются отдельно от ожидания opener и не сдвигаются временем заготовки. Сообщения ошибок, произвольные имена классов и идентификаторы разметчиков в журнал не попадают.
