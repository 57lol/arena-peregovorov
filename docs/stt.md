# STT: хедж и Scribe Realtime

С 18.10 голос — основной режим встречи, Scribe — основное распознавание, если сервер его даёт (`speech.scribe` в `/api/health`: настроен воркер `ELEVEN_RELAY_*`, нет `STT_STREAM=off`); иначе Яндекс с хеджем. В браузере `?stt=off` — только Яндекс, `?stt=scribe` — поток принудительно (до закрытия вкладки).

## Голосовой режим (основной)

- Встреча идёт голосом, без поля ввода: микрофон слушает сам, пауза отправляет реплику. «Говорить голосом / Писать текстом» и ползунок «Сколько ждать, пока я договорю» (коротко / средне / долго, по умолчанию средне) — в меню 3D, в правой колонке запасного 2D и в настройках хаба жюри; хранятся в localStorage (`peregovorka.input.v1`, `peregovorka.pause.v1`). `?voiceonly` / `?text` — принудительно до закрытия вкладки (выбор в настройках важнее). Нет микрофона, доступ запрещён или распознавания нет — текст с подписью почему. Прогоны Playwright по умолчанию идут текстом.
- Приём с конца реплики собеседника (`src/game/listen.ts`, `useVoiceTurn.ts`, `micStream.ts`): микрофон открыт всю встречу (на iPhone/iPad — только на свой ход: иначе iOS приглушает звук страницы), кадры по 20 мс с временем захвата. Звук до конца реплики собеседника + 80 мс — эхо из колонок, отбрасывается. Конец — по событию `<audio>` (ended/pause), а не опросом. Кольцо 1 с: в распознавание уходит речь с 300 мс до первого громкого кадра, даже если игра узнала о конце позже. Тишина в Scribe не уходит.
- Поток Scribe подключается заранее, когда собеседнику осталось ≤2,5 с; без речи закрывается через 6 с (воркер держит соединение 35 с от подключения); речь ограничена так, чтобы финал успел до обрыва. Свёрнутая вкладка, меню, уход, ход текстом — микрофон и поток закрываются. Не подключился ни разу — минуту сразу Яндекс.
- «Перебить» — кнопка, пока собеседник говорит (по громкости не перебиваем: без эхоподавления голос собеседника из колонок не отличить от игрока). «Готово» — отправить, не дожидаясь паузы. «Не расслышал» — слушаем дальше сами, после трёх подряд — по кнопке.
- Пауза конца фразы (`endOfTurn.ts`), мс: без текста / законченная / непонятно / оборвана на союзе — коротко 1000/600/1000/2000 (прежние), средне 1500/900/1500/2600, долго 2300/1400/2300/3600. У Scribe знаки препинания приходят с partial примерно через 0,9–1,4 с после конца речи, поэтому «коротко» на деле 0,9–1,5 с до отправки.

## Что изменилось

- `/api/stt`: две попытки максимум. Вторая стартует через `max(1500 мс, 300 мс × секунды аудио)` либо сразу после сети/5xx. Первый успешный ответ побеждает, проигравший отменяется. 4xx до старта дубля не повторяется. Таймаут каждой попытки остаётся 8 с. Сырой PCM строго до 30 с, чётное число байт.
- Бюджет атомарно проверяется и списывается перед каждой отправкой. Яндекс считает обе запущенные попытки, даже отменённую или неуспешную: консервативно, по блокам 15 с.
- `POST /api/stt/session` за gate выдаёт короткий пропуск. `STT_STREAM_VIA=server` ведёт через `/api/stt/stream`; `worker` возвращает URL воркера. Браузеру не выдаются ни API key, ни relay secret.
- Сервер проверяет gate повторно при Upgrade, сессию билета и Origin. Воркер проверяет HMAC, срок, Origin и одноразовость через Durable Object. Пропуск действует 15 с. Лимиты на вход/IP: 120 в час / 300 в сутки, можно изменить.
- Слот Scribe: 30 с аудио + 5 с на финал для voiceonly/auto; 60 + 5 с для ручного режима. Полный слот **заранее списывается в локальный бюджет без возврата**. Это верхняя оценка, не копия фактического счёта ElevenLabs. Даже неудавшееся подключение расходует слот. Цена расчёта: `STT_SCRIBE_USD_HOUR × USD_RUB / 3600`; по умолчанию $0,39/ч и расчётный курс 100 ₽/$.
- У воркера ограничены PCM-байты, длительность соединения, размер/число сообщений и очередь отправки. Воркер не является произвольным прокси: endpoint, модель, язык и формат фиксированы.
- PCM 16 кГц mono signed 16-bit LE поступает кусками по 200 мс. AudioWorklet основной, ScriptProcessor — запасной; ресемплер сохраняет дробную позицию между чанками. MediaRecorder пишет всю реплику параллельно.
- Браузер ждёт готовность всего потока 4 с (включая получение билета; вживую 0,9–1,5 с), звук до готовности копится (до 5 с), финал — до 2,5 с после commit. Любой обрыв/отказ/пустой финал переключает на полную сохранённую запись → Яндекс с хеджем. Промежуточный текст не отправляется как готовая реплика.
- В manual-режиме Scribe может сам разрезать длинный звук. Воркер коммитит сегменты каждые 20 с и отдельно последний; браузер склеивает подтверждённые сегменты, не дублируя partial.

Счётчики входов и билеты сервера живут в памяти процесса; бюджет хранится на диске, как раньше. Для нескольких процессов Passenger нужны sticky sessions и общий атомарный бюджет/лимитер — эта реализация рассчитана на существующий один процесс. Одноразовость токенов воркера от перезапуска сервера не зависит.

## Деплой

1. В папке `~/Arena-materials/tts-relay` лежат изменения `src/index.js`, новый `src/stt.js`, тесты `test/stt.test.js`, binding и миграция в `wrangler.toml`.
2. Сначала проверить и задеплоить воркер:

   ```sh
   cd ~/Arena-materials/tts-relay
   node --test test/stt.test.js
   npx wrangler deploy --dry-run
   npx wrangler deploy
   ```

   Используются существующие секреты `RELAY_SECRET`, `ELEVENLABS_API_KEY`. Если их ещё нет: `npx wrangler secret put RELAY_SECRET` и `npx wrangler secret put ELEVENLABS_API_KEY`. Значения не вписывать в wrangler.toml. Миграция `stt-v1` создаёт SQLite Durable Object `SttSession`; не удалять binding `STT_SESSIONS`.
3. На сервере установить зависимости (`npm ci`, добавлена `ws`), выставить:

   ```dotenv
   ELEVEN_RELAY_URL=https://your-worker.workers.dev
   ELEVEN_RELAY_SECRET=тот-же-секрет-что-RELAY_SECRET
   STT_STREAM_VIA=server
   STT_ORIGIN=https://ваш-публичный-домен
   STT_SCRIBE_USD_HOUR=0.39
   USD_RUB=100
   ```

   `STT_ORIGIN` — точный origin без завершающего слеша. Настроить реальные лимиты `STT_DAILY_SEC`, `LLM_TOTAL_RUB`, `STT_STREAM_SESSION_HOUR_LIMIT`, `STT_STREAM_IP_DAY_LIMIT`. Ключ Яндекса оставить для fallback. Ключ ElevenLabs серверу не нужен.
4. Собрать `npm run build && npm run build:server`, доставить `dist/`, `dist-server/` по существующей процедуре и перезапустить Passenger. В сборку фронта входит `/pcm-worklet.js`.
5. Если Passenger не пропускает Upgrade/101, сменить **только** `STT_STREAM_VIA=worker` и перезапустить сервер. Выдача токена по HTTPS всё равно проходит через gate и бюджет. Автопереключения на прямой воркер нет: при отказе выбранного пути игрок получает Яндекс.

## Проверки

Офлайн, без портов и внешней сети:

```sh
npx tsc -b
npm test
npm run lint
node --import tsx scripts/stt-e2e.ts
node --test ~/Arena-materials/tts-relay/test/stt.test.js
```

`node --import tsx` не открывает служебный IPC-сокет CLI `npx tsx`, запрещённый в sandbox. E2E подменяет сокет и fetch: PCM → partial → commit → финал, затем обрыв → полная запись → хедж → финал. Worker-тесты отдельно проверяют протокол, подпись, replay, лимиты и закрытие обеих сторон. Это проверки логики, не реального микрофона/Passenger/Cloudflare runtime.

Живой платный замер:

```sh
node --import tsx scripts/stt-live.ts ./wav 20 > stt-results.jsonl
```

Берёт первые N `.wav` по имени: RIFF PCM16 LE, mono, 16 кГц, от 0,3 до 30 с. Неверный формат отклоняется; автоматической конвертации нет. Для подготовки: `ffmpeg -i input.wav -ar 16000 -ac 1 -c:a pcm_s16le out.wav`. Скрипт читает ключ Яндекса и relay URL/secret из `.env`, генерирует отдельный короткий HMAC-пропуск для каждой фразы. **Это прямые платные API-вызовы вне бюджета/лимитов приложения.** Никаких ключей в логах; распознанные тексты попадут в JSONL.

Сравнение: обычный Яндекс (8 с и один последовательный повтор), Яндекс с хеджем, Scribe через воркер. Scribe получает звук в реальном темпе. `finalMs` — после конца аудио/начала POST для Яндекса и после последнего чанка/commit для Scribe; у Scribe также `connectMs`, `firstPartialMs` и `totalMs` с начала подключения. Это не задержка от начала речи. Порядок провайдеров чередуется, выводятся ошибки, число попыток и p50/p90/p95/max успешных ответов. Нужны десятки фраз для хвостовых задержек.

На проде проверить:

- Вход: без cookie нельзя получить билет и открыть server WS; чужой Origin, истёкший и повторный token отклоняются.
- Оба транспорта: 101 Upgrade и ready, partial, final; в Network нет API key/relay secret. Токен в query краткоживущий, но URL с ним не публиковать и не записывать в access-логи.
- HTTPS Chrome/Firefox/Safari/iPhone: разрешение микрофона, Worklet и fallback, запись первого слова, 44,1/48 кГц, отпускание микрофона после Stop/Cancel/ухода.
- «По рукам», «Согласны?», «за двести… рублей», «если…», «потому что…», продолжение после 0,8–1,5 с паузы; обычный режим не отправляет от паузы.
- Короткие фразы (<2 с), реплики 20/30/60 с, граница автоматического сегмента: весь текст один раз.
- Заблокировать WS, задержать ready >4 с, оборвать в середине и перед final: запись целиком уходит в Яндекс, один итоговый текст, «Ещё раз» сохраняет ту же запись.
- Исчерпать маленький тестовый бюджет/лимит: ни новый поток, ни хедж не обходят его; обе попытки Яндекса учтены. Сверить консервативный счёт Scribe с фактическим биллингом.
- Убедиться, что прежние TTS POST и `/voices` воркера продолжают работать.

## Сверка с документацией

Проверены официальные источники:

- [ElevenLabs Realtime API](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime): endpoint, `xi-api-key`, модель, формат, события и ручной commit.
- [Transcripts and commit strategies](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies): накопление сегментов, автоматический commit примерно через 36 с, первые результаты после примерно 2 с аудио, чанки 0,1–1 с.
- [ElevenAPI Pricing](https://elevenlabs.io/pricing/api?price.section=speech_to_text): опубликованная ставка realtime $0,39/час. В коде ставка настраивается.
- [Yandex SpeechKit sync](https://aistudio.yandex.ru/ru/docs/speechkit/stt/api/request-api): endpoint v1, сырой LPCM без WAV-заголовка, 16 кГц, mono, ограничения 30 с / 1 МБ.
- [Cloudflare WebSockets](https://developers.cloudflare.com/workers/examples/websockets/): исходящий fetch с Upgrade и серверная WebSocketPair.

Проверено вживую 17.10 (см. `~/Arena-materials/final/stt/LIVE_REPORT.md`): воркер, оба транспорта (локально), WebSocket с хостинга рег.ру до воркера. Грабли воркера: с compatibility_date 2026 бинарные кадры приходят Blob (нужен `binaryType = 'arraybuffer'`), а `AbortSignal.timeout` на fetch рвёт уже открытый upstream-сокет.

Не проверены живьём: квота одновременных STT именно у вашего Creator-аккаунта; фактические минимумы/округление биллинга и способ тарификации простоя; работоспособность Upgrade у конфигурации Passenger рег.ру; доступность workers.dev с сетей игроков в РФ; применение миграции Durable Object и лимиты вашего Cloudflare-аккаунта. Наличие API в документации не подтверждает эти свойства конкретного развёртывания.
