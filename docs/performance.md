# Производительность

Замер сборки в worktree `final/n-perf`, 18.10.2026. Сеть, браузер и реальные устройства в sandbox недоступны.

| Ресурс | До | После |
| --- | ---: | ---: |
| Весь синхронный JS титула | 773 кБ | ≈485 кБ (−37%) |
| Основной JS-чанк | 484 кБ | ≈305 кБ |
| CSS титула | 98 кБ | ≈72 кБ (−27%) |
| Отложенный 3D с three.js | 648 кБ | ≈648 кБ |

JS титула после gzip — около 160 кБ. Это сумма entry и всех его статических импортов, без динамических импортов. Сжатие для статики теперь выполняется при сборке: Node отдаёт готовые `.gz`, если клиент принимает gzip. API и потоки голоса не затрагиваются.

Повторить замер после `npm run build`: `node scripts/bundle-size.mjs`. Скрипт читает Vite manifest, учитывает общие зависимости один раз и показывает отложенные чанки. Размеры отдельных чанков нельзя считать размером всего экрана: у них есть общие зависимости.

## Загрузка

Титул остаётся синхронным; фон титула и основной шрифт получают preload. Кабинет, доска, папка дел, карта, карьера, классическая встреча, разбор, лаборатория, 3D и катсцены загружаются при открытии. 3D прогревается на брифе. Локальный расчёт при сбое API вынесен без изменений в динамический модуль.

Музыка и фон загружаются для текущей сцены. На старте из коротких эффектов прогревается только щелчок. Первая реплика использует прежний кэш `warmLine`; бриф дополнительно прогревает фразы-паузы и реакции текущего лица. Все лица сразу не загружаются.

Хэшированные ассеты: `public, max-age=31536000, immutable`. MP3: `private, max-age=2592000`, без immutable, поскольку имена не содержат версии. HTML перепроверяется; ошибки ассетов не кэшируются надолго.

## Кадры и память

DPR рендера остаётся равным 1. Буфер содержит не больше 120 тысяч игровых точек; CSS растягивает его без сглаживания. При низком FPS действует прежнее уменьшение качества и переход в 2D. При движении камеры и разговоре — до 60 FPS, в покое и при reduced motion — до 30. В скрытой вкладке 3D и катсцены останавливают RAF; после возврата не догоняют пропущенное время. Титул и карта используют тот же механизм с собственной частотой.

Материалы комнат остаются MeshBasic со светом в текстурах, без динамических теней. Освобождение геометрий, материалов, текстур и WebGL-контекста сохранено; подписчики мира и отладочные ссылки очищаются.

Кэш декодированного звука ограничен 12 элементами и 24 МиБ; активный источник продолжает держать свой буфер до завершения. Огибающие речи ограничены 96 элементами. Аудиоузлы отсоединяются после окончания. Ожидания MediaSource/SourceBuffer снимают слушатели при отмене; микрофон освобождает свои слушатели и контекст. Лаборатория отменяет запросы при остановке и освобождает blob URL.

## Диагностика

Открыть `/?perf` или `/?jury&perf`. В углу и раз в пять секунд в консоли:

- FPS интерфейса и отдельно число реальных 3D-кадров;
- размер буфера 3D;
- `UI готов` — время от начала навигации до первого коммита интерфейса React (приближение TTI, не метрика Lighthouse и не время ответа API);
- `heap` — JS-память, если браузер предоставляет `performance.memory`; в остальных браузерах «н/д». Это не вся память GPU/аудио.

Без `?perf` плашка, её модуль и цикл измерения не загружаются/не запускаются. Показание UI ограничено частотой диагностического цикла, до 60 FPS. При скрытии вкладки измерение приостанавливается.

## Проверить вживую

1. Холодная загрузка с мобильной сетью: на титуле нет three.js, лаборатории, разбора, чужих голосов и музыки других экранов. В Network проверить `Content-Encoding: gzip`, `Vary` и Cache-Control JS/CSS/MP3. После повторного визита ассеты берутся из кэша.
2. С титула пройти сюжет и путь жюри, кабинет → доска, катсцены → галерея, разбор → переигровка. Проверить «Назад», перезагрузку во встрече и продолжение партии. На статическом хостинге без API локальная встреча должна работать как раньше.
3. Safari/iPhone и Android: первый клик разрешает голос, первая реплика и первая реакция звучат вовремя; нет двойной озвучки. Проверить отключение/включение голоса, микрофон, прерывание потока и уход со встречи во время запроса.
4. Слабый ноутбук/телефон с `?perf`: в покое около 30 3D FPS, во время движения до 60; вкладка в фоне не рендерит. При реальной нехватке скорости сначала снижается разрешение, затем сохраняется рабочий 2D-режим.
5. Пять-десять встреч подряд, каждый раз с разбором: сравнить heap после сборки мусора, число WebGL-контекстов и аудиоконтекстов. Память не должна расти на каждую встречу; смена музыки может временно держать два буфера для плавного перехода.
6. Ширина 320/390 px и горизонтальная ориентация: нет горизонтальной прокрутки, важные кнопки доступны пальцем, меню и ввод вне выреза и нижней полоски iPhone. Открыть клавиатуру в текстовом режиме, отправить реплику и закрыть клавиатуру.
7. Включить «Уменьшение движения»: нет CSS-анимаций, дыхания камеры и подскоков портретов; сюжет, реплики и управление продолжают работать.
